# 导出对话框简约工厂风格设计

## 目标

将现有导出对话框改为简约、工具化的侧栏工位布局，减少 AI 风格的卡片、圆角、渐变和装饰文案。导出流程需要支持更多格式、真实设置，并通过统一的预览中间结构保证导出内容与预览内容一致。

## 界面结构

使用 B 方案的侧栏布局：

- 左侧导航仅包含“导出格式”和“导出设置”。
- 右侧显示当前导航对应的功能内容。
- 格式使用紧凑的可选列表，不使用格式介绍卡片。
- 底部固定显示“取消”和“开始导出”。
- 不增加产品介绍、营销文案、装饰性副标题或无功能说明。
- 视觉使用灰白背景、深灰标题、细边框、低圆角和少量动效。

## 导出格式

格式注册表扩展为：

- Markdown（`.md`）
- HTML（`.html`）
- 纯文本（`.txt`）
- JSON（`.json`）
- YAML（`.yaml`）
- CSV（`.csv`）
- XML（`.xml`）
- PDF（`.pdf`）
- DOCX（`.docx`）
- ODT（`.odt`）

每个格式必须拥有明确的转换函数、扩展名、默认文件名和保存过滤器。无法在当前运行环境中可靠生成的格式不能伪装成已完成，必须提供可识别的错误反馈。

## 导出设置

设置需要实际影响输出，不做无效占位：

### 通用设置

- 导出文件名
- 保存位置
- 同名文件处理
- 图片处理方式：保留原链接或嵌入数据
- 是否保留任务列表状态
- 是否保留代码语言标识

### HTML 设置

- 页面标题
- 是否内嵌样式
- 是否生成完整 HTML 文档

### PDF、DOCX、ODT 设置

- 页面尺寸
- 页面方向
- 页边距
- 是否显示页眉页脚
- 是否显示页码
- 是否保留标题、表格、图片和代码块结构

### CSV、JSON、YAML、XML 设置

- UTF-8 编码
- 是否包含元数据
- 表格和正文的转换规则
- 是否保留 Markdown 标记

## 预览一致性

导出流程使用统一的中间文档结构：

```text
当前编辑内容 → 统一 HTML/文档结构 → 预览与导出
```

HTML、PDF、DOCX、ODT、TXT 等面向呈现的格式必须基于和预览一致的结构生成，保留标题、段落、列表、任务列表、表格、代码块、图片、链接和分隔线。Markdown、JSON、YAML 等结构化格式保留原始语义，并在设置允许时附带元数据。

## 交互流程

1. 打开导出对话框，默认进入“导出格式”。
2. 选择格式后进入或切换到“导出设置”。
3. 设置只显示当前格式适用的选项。
4. 点击“开始导出”。
5. 校验设置并调用对应转换器。
6. 调起保存位置选择或使用已选位置。
7. 写入文件并显示成功或失败状态。
8. 成功后关闭对话框，失败时保留当前设置并显示可操作错误。

## 验证要求

- 现有 Markdown、HTML、TXT、JSON 导出能力不能回归。
- 预览中存在的标题、列表、任务列表、表格、代码块、图片和链接在可呈现格式中均应保留。
- 每种格式的文件扩展名和保存过滤器一致。
- 导出设置必须能通过实际输出验证。
- 导出对话框在窄窗口下仍可操作。
- TypeScript 类型检查和项目构建必须通过。
